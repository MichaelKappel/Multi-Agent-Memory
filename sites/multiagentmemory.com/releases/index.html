Publication standard

The evidence bar for every entry

Each record must answer the questions a user, operator, or auditor needs without exposing private deployment details.

  1. 01

    Exact identity

    A three-part website semantic version and one production activation date.

  2. 02

    User-visible change

    Plain-language changes and milestones that describe what people can actually use.

  3. 03

    Separate scopes

    Website, endpoint API, schema, and package identities stay distinct instead of borrowing one version label.

  4. 04

    Public evidence

    Version-bound, public-safe links support the record. Private paths, credentials, payloads, and internal identifiers never do.

Version clarity

One release can have several version scopes

The label beside a number matters. These identities are related only when a verified release record explicitly binds them.

Website version
The semantic version assigned to an activated MultiAgentMemory.com static-site release.
Endpoint API version
Owned by the separately deployed MemoryEndpoints.com runtime; this companion site never inherits it.
Ledger schema version
Describes the releases.json document contract. It is not the website version.
Package or source identity
A repository revision or deploy artifact is evidence input, not a public website version by itself.
